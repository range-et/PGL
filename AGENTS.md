# Repository workflow

Use GitHub issues in `range-et/PGL` as the backlog for issue-driven work.

1. Triage relevant open issues before implementation: read their descriptions and
   discussion, check the current code, identify duplicates and dependencies, and
   establish scope, priority, and acceptance criteria.
2. Complete the selected issue's implementation and required verification. Follow
   the testing and coverage policies in `CONTRIBUTING.md`. Do not treat partial
   implementation or passing coverage alone as completion.
3. After the work is complete and verified, add an entry to `features.md` linking
   the GitHub issue and describing the delivered behavior, verification results,
   and any compatibility implications or remaining limitations.

Keep planned or unfinished work in GitHub issues, not in the completed-work log.
Do not claim an issue is resolved until its acceptance criteria are met. Respect
the user's selected scope and any instruction to defer work; this workflow does
not automatically start every open issue.
